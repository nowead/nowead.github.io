{{ if eq $kind "medical-volume" }}
  1. 01

    파일의 좌표를 영상의 좌표로

    DICOM의 픽셀값과 공간 정보를 읽고 슬라이스를 정렬합니다. 방향을 정규화해 탐색 가능한 볼륨으로 구성합니다.

  2. 02

    3D·2D 보기를 하나의 엔진에서

    3D ray marching과 세 방향 단면을 렌더링합니다. Window/Level, 품질 설정과 카메라 조작을 엔진 API로 제공합니다.

  3. 03

    도착하는 마스크를 점진적으로 합성

    팀의 AI 추론 결과를 슬라이스별로 GPU에 반영합니다. 이전 볼륨의 마스크를 거르는 volumeId 검증은 Shell이 담당합니다.

{{ else if eq $kind "delivery-loop" }}
  1. 01

    요청을 요구사항으로

    요청을 그대로 구현하지 않습니다. 확인 질문으로 범위를 정하고, 번호가 붙은 요구사항과 결정 기록으로 남깁니다.

  2. 02

    테스트가 완료 기준

    요구사항마다 테스트를 연결합니다. 테스트, 화면 회귀, 운영 구성 점검을 하나의 명령으로 실행합니다.

  3. 03

    운영이 다음 요청으로

    배포한 뒤 실제 사용에서 나온 피드백이 다시 요구사항이 됩니다. 이 순환을 계속 반복합니다.

{{ else }}
  1. 01

    렌더링 의도를 공통 인터페이스로

    GPU 자원과 렌더링 명령을 RHI 인터페이스로 정의합니다. 상위 렌더러는 이 기반 위에서 장면과 패스를 구성합니다.

  2. 02

    설정에 따라 백엔드를 선택

    RHIFactory가 Vulkan 또는 WebGPU Device를 생성합니다. RendererBridge는 렌더러와 공통 RHI를 연결합니다.

  3. 03

    API의 차이를 고려한 구현

    공통 로직을 재사용하면서도 동기화, 자원 관리와 프레임 수명은 각 백엔드의 제약에 맞게 다룹니다.
